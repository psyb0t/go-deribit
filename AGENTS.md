# go-deribit

Unofficial Go client for Deribit, generated from its published OpenAPI and AsyncAPI documents. To use the client from an agent, read [.agents/skills/go-deribit/SKILL.md](.agents/skills/go-deribit/SKILL.md); this file is about changing the code.

## Architecture

Two generated packages, each driven by its own `gen.go`:

- REST, package `deribit` at the root: `scripts/fetch-spec.sh` downloads `https://docs.deribit.com/specifications/deribit_openapi.json` into `api/`; `scripts/patch-spec.sh` writes `api/openapi.fixed.json`; oapi-codegen with `config.yaml` writes `client.gen.go`.
- WebSocket, package `deribitws` in `ws/`: the AsyncAPI download comes from `https://docs.deribit.com/specifications/deribit_asyncapi.json`; `scripts/patch-asyncapi.sh` writes `api/asyncapi.fixed.json`; gen-asyncapi with `ws/config.yaml` writes `ws/deribitws.gen.go`.

## Stack

- Go 1.26.9.
- oapi-codegen and gen-asyncapi, pinned as `tool` dependencies in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime` and `github.com/psyb0t/gen-asyncapi/asyncapirt`.

## Layout

- `gen.go`, `config.yaml`, `client.gen.go`: the REST package.
- `client_test.go`, `example_test.go`: REST tests and the README example.
- `ws/`: WebSocket generation, configuration and decoding tests; `ws/testdata/` holds schema-shaped JSON-RPC frames.
- `scripts/`: spec downloads, patches, lint and security scanning.
- `api/`: downloaded and patched specs, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- REST GET request bodies contain JSON-RPC examples without schemas. The patch removes those examples from the REST operation bodies, preserves all 186 paths and assigns operation IDs from complete paths. REST methods use query parameters.
- The published REST spec omits security schemes. Private requests need an OAuth bearer token supplied by a request editor. The `/public/auth` parameter requirements mix mutually exclusive grant types; the generated signature preserves those requirements.
- The AsyncAPI document describes subscription data rather than complete wire frames and has inverted operation message references. Its patch restores JSON-RPC envelopes and the client send/receive directions while preserving all 43 channels and 86 operations.
- The WebSocket patch fixes quote required-field typos, nullable numeric fields and explicitly formatted single-precision floats. Raw user-order channels overlap interval channels, so only the receive matcher excludes raw intervals where a dedicated raw channel exists.
- Private subscription methods apply to user channels and private block channels. `block_rfq.trades.{currency}` stays public. Raw market-data channels require authentication even when their method is `public/subscribe`.
- WebSocket authentication, unsubscribe calls and JSON-RPC replies have no schemas in the downloaded subscription document. The caller handles those on the supplied transport; the generated package covers subscriptions and notifications.
- Both patches reconcile repeated array payloads and nullable fields with the provider examples and descriptions. The WebSocket patch also repairs order flag booleans, maker strings and sparse incremental ticker statistics. Preserve item schemas when wrapping incorrectly declared objects in arrays.
- Block trade confirmation notifications require `app_name` according to the schema even though the example omits it. Strict decoding preserves that requirement.
- Both patches normalize descriptions for generated comments without changing wire values.
- Keep the REST `number` to `float64` mapping. Without it, prices and amounts become `float32`.
- `make generate` downloads the current specs, so it can change the client even when nothing here changed. Review the generated diff.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
